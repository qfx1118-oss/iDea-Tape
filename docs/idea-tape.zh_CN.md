# 灵感磁带设备固件

公开项目：https://github.com/qfx1118-oss/iDea-Tape 。

## 按键

按住上键录音，松开保存；下键开始持续录音，再按结束保存。短按 OK 进入录音列表，上下选择、OK 播放或停止。长按上/下申请删除，OK 确认、上下取消。长按 OK 返回待机；待机长按 OK 打开 Wi-Fi 导出，电脑连接屏幕显示的 iDea-Tape 热点及密码，浏览器打开 http://192.168.4.1 试听、下载 WAV，长按 OK 关闭导出。Wi-Fi 导出与 BLE 会话互斥。

待机时配对安卓 App，设备显示六位配对码并进行身份验证。录音中传送音频块，结束后补齐缺失片段。手机反馈的已收块数驱动进度显示；只有最终保存确认匹配且缓存删除成功，才显示 100% 与完成。暂停/断线保留录音。设备录音、播放、手动删除确认和导出期间保护存储，避免后台删除冲突。

## 存储与时序

机内使用 16kHz 单声道 IMA ADPCM（256 字节块、505 采样），导出 PCM WAV。缓存合计约六至七分钟，最多 64 段，即使实时传输也非无限容量。位置来自手机的新鲜录音起点定位，设备不独立获取 GPS。转轴动画与停止音频分离：加减速、多转 16 度、回退 4 度，再阻尼停稳。工作任务拥有状态，LVGL 通过加锁快照读取。

BLE 使用 NUS UUID、身份验证与加密。帧含版本/类型/长度/CRC，录音身份包含持久 ID 和随机 token。最终删除检查完整状态、身份、块数与 CRC。手机先同步写入 WAV 和资料，再发送 COMMIT。实现及主机测试见 main/tape_protocol.*、main/tape_sync.*、tests/test_tape_protocol.c。这是应用协议，不声称能抵抗已完全被控制的配对手机。

## 构建与发布文件

使用 ESP-IDF 5.5.3：

```sh
./tools/validate.sh --static
./tools/validate.sh --firmware
./tools/validate.sh
```

完整验证核对分区并保留匹配 ELF/MAP/应用/引导/分区归档，发布前用 tools/archive_firmware.py 验证。公开完整镜像补齐擦除字节到整个 8MB 布局，初次刷写会清除旧 NVS 与录音，必须明确告知并先导出重要录音。

兼容升级若需保留数据，使用已验证引导 0x0、分区表 0x8000、应用 0x10000 分段写入，不可用跨越 NVS 的合并镜像替代。录音分区仍从 0x310000 开始，保留数据升级不得擦除。刷写需单独授权，发布不等于获准刷写。

## 验证边界

前序开发版由用户确认过设备录音/保存/回放、Wi-Fi 导出、安卓配对、音频同步、位置记录、自动删除、锁屏接收和手机自身录音。传输界面已主机渲染查看。开源发布会重新执行构建和主机测试，这不等于新地图 APK 或全部固件交互完成真机验收。断线补传、地图联网、长时间、权限/空间异常及更多手机兼容性仍待验证。封面和配图明确标识为渲染，无设备凭据。

## 0.5.0 地点显示

可选的加密认证蓝牙 PLACE 消息（类型 21）包含状态、UTF-8 长度及最多 96 字节地点。严格检查 UTF-8、状态和长度，拒绝异常输入。状态 0 清除、1 等待定位或解析、2 显示手机提供的地点、3 提示地址不可用。工作任务在 25 秒无刷新或断开连接后清除临时地点，通过加锁快照更新屏幕。12 像素字体补齐字体源支持的基本汉字至 U+9FEF，其他界面字号保持原有子集。录音存储分区不变。用户已确认 0.4.0 全部测试通过，以及 0.5.0 设备界面和手机推送道路名正常。

## 0.6.0 息屏待机

30 秒没有按键操作后关闭背光并暂停界面刷新，录音、播放、蓝牙和存储继续运行。任意键唤醒；首次唤醒手势含长按和松开事件均不触发原操作，再次按键正常使用。按住录音及配对码显示期间保持亮屏；新配对提示会亮屏。蓝牙持续可用，断线后手机按重连策略恢复。这是息屏待机，并非深度休眠，尚未测得全天续航。分区及已有录音布局不变。
